## 🎯 Описание проекта

Находится в разработке

Система учета и записи автомобилей на детейлинг услуги служит помощником для детейлинг центров и клиентов. Менеджерам удобно записвать автомобили на обслуживание, фото-видеофиксировать автомобиль во время приемки и после проделанных работ, хранить базу данных обслуживаемых автомобилей, какие услуги предоставлялись

- **Управлять заказами**: создание, отслеживание статусов, обновление
- **Обрабатывать события**: асинхронная обработка через Kafka (планируется)
- **Кешировать данные**: быстрый доступ через Redis
- **Мониторить состояние**: health checks и метрики

## 💡 Планируемый функционал

### 1. Система записи клиента

#### Основная идея

В детейлинг центре менеджеры могут записать клиента, его автомобиль. При оформлении заказа, менеджер может выбрать необходимые услуги из списка услуг. Цену для каждой услуги менеджеры будут заносить самостоятельно (сделано это потому, что автомобили бывают разного размера, повреждения, загрязнения и объем работ тоже бывают разными даже для одной и той же услуги для одного и того же автомобиля). Так же будет заноситься марка и модель автомобиля, гос номер и вин номер. В поле с описанием будут заноситься все текущие повреждения автомобиля при первичном осмотре. Так же можно будет добавлять фото и видео автомобиля и его повреждений при приемке

### 2. Админ панель

#### Основная идея

В админ панели можно просмотреть все записи клиентов, стоимости работ
Так же в админ панели будет предусмотрена статистика, аналитики продаж

### 3. Телеграм бот

#### Основная идея

Владельцу бизнеса будет удобно наблюдать с мобильного устройства через приложение Telegram какие заказы сейчас активны, в каком они статусе, на какой сумму

### Компоненты системы:

1. **HTTP API**: RESTful API без внешних фреймворков
2. **Business Logic**: Сервисы для обработки бизнес-логики
3. **Data Layer**: PostgreSQL для персистентности, Redis для кеширования
4. **Event System**: Kafka для асинхронной обработки событий (планируется)
5. **Monitoring**: Health checks и логирование

## 📊 Мониторинг

### Health Checks

Система предоставляет несколько эндпоинтов для мониторинга:

- `/health` - полная проверка здоровья всех компонентов
- `/health/readiness` - готовность к обслуживанию запросов
- `/health/liveness` - жизнеспособность приложения

### Соглашения по коду

1. **Именование**: camelCase для переменных, PascalCase для типов
2. **Обработка ошибок**: всегда обрабатывайте ошибки явно
3. **Логирование**: используйте структурированные логи с контекстом
4. **Тесты**: покрытие должно быть не менее 80%

### Добавление новых API

1. Создайте модель в `internal/models/`
2. Добавьте бизнес-логику в `internal/services/`
3. Создайте HTTP обработчик в `internal/handlers/`
4. Зарегистрируйте маршрут в `cmd/server/main.go`

### Миграции БД

Для добавления новой миграции:

1. Создайте файлы `XXX_name.up.sql` и `XXX_name.down.sql` в папке `migrations/`
