# Публичные формы сайта: заявка и отзыв

Инструкция для фронтенда: как отправлять формы заявки и отзыва, чтобы защита от спама
не мешала настоящим посетителям.

| Форма | Запрос |
|---|---|
| Заявка | `POST /api/v1/leads` |
| Отзыв | `POST /api/v1/reviews` |

Обе формы без авторизации, тело — JSON (`Content-Type: application/json`).

## Как бэкенд защищает формы

1. **Лимит запросов с одного IP**: заявки — 5 за 10 минут, отзывы — 3 за час (значения
   могут меняться в настройках сервера).
2. **Скрытое поле-ловушка `website`**: человек его не видит и не заполняет, бот заполняет.
3. **Повтор по телефону**: вторая заявка с тем же телефоном в течение 10 минут (отзыв — в течение
   суток) отклоняется.

Чтобы это работало правильно, фронтенду нужно выполнить пункты ниже.

## 1. Отправлять форму из браузера

Лимит считается по IP посетителя. Запрос должен уходить из браузера (`fetch`/`axios`)
на `/api/...` того же домена — nginx передаст бэкенду реальный IP посетителя.

**Нельзя** отправлять форму с сервера фронтенда (SSR, server actions в Next.js, серверные
API-роуты Nuxt и т.п.): тогда у всех посетителей для бэкенда один IP — IP сервера фронтенда,
и лимит в 5 заявок за 10 минут станет общим на весь сайт.

Если отправка через сервер фронтенда неизбежна — согласовать с бэкендом: сервер фронтенда
должен передавать `X-Forwarded-For` с IP посетителя, а его адрес добавляется в
`TRUSTED_PROXIES` бэкенда.

## 2. Добавить скрытое поле `website`

```html
<div style="position:absolute; left:-9999px;" aria-hidden="true">
  <label>
    Website
    <input type="text" name="website" tabindex="-1" autocomplete="off">
  </label>
</div>
```

- Прятать через CSS, **не** через `type="hidden"` — такие поля боты распознают и не заполняют.
- `tabindex="-1"` и `aria-hidden` — чтобы человек не попал в поле с клавиатуры или скринридера.
- Отправлять значение поля как есть (у человека оно пустое): `"website": ""`. Можно не отправлять
  вовсе. Самим заполнять нельзя — такая заявка будет молча отброшена.

## 3. Любой ответ `201` — успех

Боту, заполнившему ловушку, бэкенд отвечает `201` с пустым объектом `{}` — чтобы он не понял,
что его отсекли. Поэтому:

- на `201` всегда показывать «Спасибо!», не опираясь на поля ответа (`id` и т.п.);
- для отзыва — «Спасибо! Отзыв появится на сайте после проверки».

## 4. Блокировать кнопку на время отправки

Пока запрос выполняется, кнопка «Отправить» должна быть неактивна. Иначе двойной клик отправит
вторую заявку с тем же телефоном — она получит `429`, и человек увидит ошибку, хотя первая
заявка прошла.

## 5. Обработка ответов

| Статус | Что означает | Что показать |
|---|---|---|
| `201` | Принято | Сообщение об успехе (см. п. 3) |
| `400` | Ошибка в данных | Подсветить поля. `message` в ответе — технический текст на английском, лучше показывать свои тексты |
| `429` | Слишком много попыток | «Слишком много попыток, попробуйте позже» |
| `5xx` | Ошибка сервера | «Что-то пошло не так, попробуйте ещё раз» |

При `429` **не повторять запрос автоматически**. Через сколько секунд можно повторить — в
заголовке ответа `Retry-After` (при превышении лимита по IP), его можно показать пользователю.
Ответ `429` не уточняет причину (лимит по IP или повтор телефона) — это сделано намеренно.

Тело ответа с ошибкой:

```json
{ "error": "Too Many Requests", "message": "too many requests, please try again later" }
```

## 6. Формат данных

### Заявка — `POST /api/v1/leads`

```json
{
  "name": "Иван",
  "phone": "+7 (999) 123-45-67",
  "email": "ivan@example.com",
  "message": "Нужен сайт для компании",
  "service_id": 3,
  "source": "contact_form",
  "website": ""
}
```

| Поле | Обязательное | Правила |
|---|---|---|
| `name` | да | до 100 символов |
| `phone` | да | международный формат с `+`; пробелы, скобки и дефисы допустимы |
| `email` | нет | корректный email, до 255 символов |
| `message` | нет | до 5000 символов |
| `service_id` | нет | ID услуги из `GET /api/v1/services` |
| `source` | нет | откуда заявка (по умолчанию `contact_form`), до 100 символов |
| `website` | — | ловушка, см. п. 2 |

### Отзыв — `POST /api/v1/reviews`

```json
{
  "name": "Иван",
  "phone": "+7 (999) 123-45-67",
  "email": "ivan@example.com",
  "rating": 5,
  "text": "Отличная работа!",
  "website": ""
}
```

| Поле | Обязательное | Правила |
|---|---|---|
| `name` | да | до 255 символов, показывается на сайте |
| `phone` | да | как у заявки; на сайте **не показывается** |
| `email` | нет | до 100 символов; на сайте **не показывается** |
| `rating` | да | целое число от 1 до 5 |
| `text` | да | до 5000 символов |
| `website` | — | ловушка, см. п. 2 |

## Локальная разработка

На сервере фронтенд и API на одном домене. Локально, чтобы было так же, настройте прокси
в dev-сервере фронтенда вместо прямых запросов на `localhost:8080`:

```js
// vite.config.js
export default {
  server: { proxy: { '/api': 'http://localhost:8080' } },
}
```

В Next.js — через `rewrites` в `next.config.js`. Бэкенд поддерживает и кросс-доменные запросы
(CORS), но с прокси локальное окружение ближе к боевому.
