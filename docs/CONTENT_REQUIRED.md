# Контент, который нужно предоставить вручную

Сайт не публикует вымышленные кейсы, отзывы, метрики и контакты. Ниже — что заполнить для production.

## Обязательно

1. **Контакты компании** — телефон, email, Telegram/WhatsApp/VK через админку `contact_info` (после деплоя API `GET /api/v1/contact-info`).
2. **Каталог услуг** — названия, описания, при необходимости ориентиры цены (`services`).
3. **FAQ** — вопросы/ответы под реальные условия работы (`faq`).
4. **Юридическая политика ПДн** — заменить заглушку `/privacy` утверждённым текстом, реквизитами оператора, сроками хранения.
5. **Кейсы / портфолио** — материалы проектов (название, тип продукта, отрасль, задача, решение, скриншоты, подтверждённые результаты, технологии). Сейчас сущности в backend нет — нужна модель + API или согласованный контент-файл.
6. **Баннеры** (опционально) — hero-изображения по страницам (`pages` + `banners`).
7. **Отзывы** — только реальные; модерация через админку (`reviews`).
8. **Диапазоны бюджета в брифе** — подтвердить или править `web/src/content/brief.ts` (`budgetRanges`).
9. **Домен и `NEXT_PUBLIC_SITE_URL`** — для SEO/OG/sitemap.
10. **Соцсети** — только подтверждённые URL (через contact_info или отдельный конфиг).

## Не придумывать

- Количество клиентов, выручку, % роста, «ТОП» рейтинги.
- Отзывы и логотипы клиентов без разрешения.
- Адрес офиса и телефон «для красоты».

## Технические зависимости

- Запущенный `nexera_back` + Postgres/Redis для живых форм и контента.
- CORS/nginx same-origin: фронт проксирует `/api` и `/media` (см. `web/next.config.ts`).
- Telegram-уведомления о лидах — outbox/Kafka пока не подключены; заявки всё равно пишутся в БД.
